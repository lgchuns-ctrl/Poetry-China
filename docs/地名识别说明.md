# 地名识别说明

## 一、方法概述

本项目采用**基于词典+规则**的命名实体识别（NER）方法，从唐诗宋词文本中提取地理地名。该方法虽不及深度学习模型灵活，但在古典文本场景下具有以下优势：

1. **可控性强**：每条识别结果可追溯到词典条目，便于验证和调试。
2. **精确率高**：通过排除词表和重叠预防机制，有效减少误识别。
3. **无需训练数据**：古典文本缺乏大规模标注语料，词典法无需训练。
4. **可解释性好**：识别过程完全透明，便于学术审查。

## 二、地名词典

### 词典规模
- **条目数**：190+
- **覆盖类别**：城市、山岳、河流、湖泊、关隘、建筑、历史区域、其他
- **文件位置**：`data/dictionary/place_dictionary.py`

### 词典结构

每条记录包含以下字段：

```python
{
    "place_name": "长安",           # 地名
    "place_name_normalized": "长安", # 规范化名称
    "place_type": "city",           # 类型
    "historical_name": "长安",      # 历史名称
    "modern_name": "西安",          # 现代名称
    "modern_province": "陕西",      # 现代省份
    "modern_city": "西安市",        # 现代城市
    "longitude": 108.94,            # 经度
    "latitude": 34.27,              # 纬度
    "mapping_level": "city",        # 映射级别
    "mapping_source": "dictionary", # 映射来源
    "aliases": ["镐京", "大兴"]     # 别名
}
```

### 别名机制

词典支持别名映射，例如：
- 镐京 → 长安
- 临安 → 杭州
- 建康 → 南京
- 汴京 → 开封
- 金陵 → 南京

别名同样参与文本匹配，匹配后统一映射到规范名称。

## 三、识别算法

### 核心流程

```
输入文本 → 构建匹配索引 → 逐字符扫描 → 词典匹配 → 排除词过滤 → 重叠预防 → 输出地名列表
```

### 详细步骤

1. **构建索引**：将所有地名和别名建立 `名称→索引` 的映射表。
2. **文本扫描**：对每首诗词的标题和正文进行扫描。
3. **词典匹配**：在文本中查找词典中出现的地名（含别名）。
4. **排除词过滤**：过滤掉与排除词表匹配的结果。
5. **重叠预防**：当两个地名在文本中位置重叠时，优先保留较长的一个（如"终南山"优先于"南山"）。

### 排除词表

以下词汇虽含地名成分，但在诗词中通常不指地理实体，故排除：

| 排除词 | 排除原因 |
|--------|----------|
| 南山 | 常泛指南面的山，非特指 |
| 东风 | 指春风，非地名 |
| 西楼 | 建筑泛称，非特指 |
| 北窗 | 建筑泛称 |
| 东篱 | 陶渊明意象，非特指 |
| 南浦 | 常作送别意象 |
| ... | 共 30+ 条 |

## 四、NER 质量验证

### 验证方法

1. **随机抽样**：从全部 5,341 条地名提及中随机抽取 150 条。
2. **人工核查**：逐条检查提取的地名是否在原文中确实出现且指地理实体。
3. **遗漏检查**：人工浏览部分文本，记录可能遗漏的地名。

### 验证结果

| 指标 | 结果 |
|------|------|
| 抽样数 | 150 条 |
| 正确数 | 150 条 |
| 精确率 | 100% |
| 可能遗漏 | 少量小地名和冷僻地名 |

### 局限性

1. **召回率有限**：词典法无法识别未收录的地名，尤其是小地名和冷僻地名。
2. **歧义处理**：部分地名在不同语境下可能指不同地点（如"东山"可指谢安隐居地或泛指）。
3. **地名边界**：古籍文本缺乏标点，地名边界判断可能受影响（但本项目数据已有标点）。
